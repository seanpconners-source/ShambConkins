## Implemented boundary

One shared mission uses the matching ID/stageId among jungle, factory, city, desert. The adapter calls `s.canvas(700,390,{fill:true})`, `s.frame`, sets shared/cooperative flags, and uses the existing session ready overlay with a three-second countdown and controls/extraction instructions. A Help button reopens the instructions during play. Scoped engine-owned CSS fills the game shell, hides duplicate chrome and preserves Pause/Exit; removal restores the scoped classes/styles.

The main players are never passed by reference into simulation. Detached owner/name/character/fighterId values begin with the board's selected character, with BF-17 owner-aligned fighter snapshots. The mission receives each player's `fighters` array; its returned state also receives `fightersByOwner` for BF-16. Simulation/rescues must retain those snapshots and keep fighter swaps inside the mission.

Attempt handoff is deliberately explicit: fresh stable identity may be supplied as `s.attemptId`; saved metadata is `s.broforceAttempt` or matching `store.run.pending.bf`, containing `{attemptId,stageId,seed?,devilId}`. Seed defaults to a hash of attemptId/stageId. A saved attempt without its latched devil, with a mismatched stage, invalid seed/ID or no longer eligible devil is rejected without reroll. BF-17 chooses only for a fresh attempt, using an isolated deterministic stream. A bounded fallback token derives from stage/session seed/player identities for reproducible practice; **it is not durable recovery**, and the host does not persist it. BF-37 must establish/save the full attempt before launch.

BF-18 owns physical pointer assignment, independent held jump/fire and desktop bindings. The host supplies a narrow held-action bridge for E/Shift or the correct owner's special button because BF-18 samples only special press edges. Menu-focused keys cannot become gameplay actions. Inputs clear on pause, menu/Exit actions, blur, visibility loss, orientation/resize and reduced-motion changes. Ambience starts/resumes only on a playing user gesture; SFX and ambience stop/pause with interruption and dispose on exit. BF-19 adapts one shared camera in world pixels; the compositor alone applies scene zoom, with cinematic callbacks explicitly receiving zoom=1 to avoid double scaling. Reduced motion affects rendering while the camera continues following players.

The portrait cache uses local data/blob images from portraitURL/fallback/headDisplayURL, never accepts an online image URL, loads once per identity and has a 128-entry bound. It clears image sources/handlers on disposal. The host disposes controls, ambience, SFX, scoped DOM/CSS and per-stage references before finish callback. No host timers or additional animation loop are created.

Terminal metadata is checked against the latched attempt/stage/devil and exact schema/outcome/two-player booleans. It is copied into `s.teamResult.bf`, with kind/won/tied/humanTotal/cpuTotal/cpuScores/duration. Scores are display-only 0/1 live-extraction indicators. P1-only, P2-only and both are valid; no living boarder means no win. Invalid terminal data stops the attempt as failure with zero scores. The settlement guard calls `s.finish` once. Cancellation never calls finish. No host recruitment, profile save, run mutation, XP or generic rewards occur.
