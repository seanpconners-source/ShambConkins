## Reproducible findings and corrections

The exact pinned source was executed as a pure JavaScript module against deterministic fixtures. Before the fix:
1. A `damageEvents` entry containing only `{targetId:'devil',damage:6}` reduced HP 36→30 without a physical hit identifier.
2. Two events with different `id` but the same `projectileId` reduced HP 36→30 rather than 36→33 when each requested 3 damage.
3. A boss-owned hit with `owner:'devil'` and `targetId:'devil'` reduced HP 36→30, allowing feedback/self-damage.
4. A 240px/s projectile passed completely across a one-pixel player body in one tick without generating `devil-hit-player`.

The production-only fix requires a stable physical hit identity (preferring `projectileId`, then combat `source`, legacy `id`/`eventId`), rejects explicitly hostile owner/source prefixes, preserves filtering on the actual boss target ID, and performs deterministic subpixel-spaced projectile sweep checks against terrain and live-player bodies. Implausible injected projectile travel over 64px in one fixed tick is discarded; internally fired rounds travel under 5px/tick. Existing impact events, HP caps, phases, tell/attack timings, pause gates and single defeat/death events remain owned by BF-20.
