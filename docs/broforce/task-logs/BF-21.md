## Exported API and contract

`Object.assign(exports,{createBroforceExtraction,advanceBroforceExtraction})`:

- `createBroforceExtraction({x,y,seed=1}={})` creates a plain-data, unactivated helicopter objective at world-pixel boarding center `x,y`.
- `advanceBroforceExtraction(state,{dt,devilDefeated=false,players=[],boardRequests=[],paused=false,cancelled=false,aborted=false}={})` returns a new state; input, previous state, player data and request lists are not mutated.
- `dormant -> incoming (2.4s) -> hover (9.0s boarding window) -> departure (2.2s) -> completed`, or `failed` after no boarding / cancellation. A boss-defeat flag triggers exactly one arrival. All timers are *active* seconds; pause freezes physics visuals, rotor and boarding. Long frame deltas cross deadlines without extending the window.
- `zone:{x,y,radius:44,open,secondsRemaining}` and `helicopter:{x,y,visible,rotorPhase,rotorAngle,rotorHz,progress}` provide deterministic UI timing/placement for the integrator; no canvas, DOM or sound API is called.
- `players[0]` must have stable `owner:'Sean'`, `players[1]` stable `owner:'Amber'`. Bodies with `w/h` use their centers; position-only actors use x/y. Valid living state requires explicit alive/positive health and no death/dying/downed status. Requests may be `[true,false]`, numeric player index, stable id, owner string, or matching keyed selector objects. Requests are consumed once, **at frame end** and only if the window is still open.
- Latches `boarded:[bool,bool]`, and immutable-step receipt records `{playerIndex,playerId,owner,boardedAt}`. P1-only, P2-only and both are valid extracted outcomes. An unboarded or dead participant never gets a qualifying receipt. When both board, departure starts early; with one aboard, departure starts when the window closes. No boardings after timeout. Aborts explicitly return failed outcome even if someone boarded.
- `events` is an *ephemeral per-advance* array with monotonic `sequence`; `cue` names map to BF-26 `helicopter`, `extraction`, `win`, `lose` sounds. `boarded` includes ownership. Exactly one `terminal` event carries `{outcome:'extracted'|'failed',reason,boarded,receipts}`. Later advances emit no duplicates. **No rewards, profiles, saves, board selected characters or roster changes occur here.**
