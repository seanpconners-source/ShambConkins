## Reproducible defect / fix
- At pinned base, the cinematic `drawPortrait` callback returned **true** when an image painter returned **false** or threw; reproduced against the original real CommonJS compositor and art modules (both failure cases returned true).
- BF-32 uses that boolean to decide whether to draw its original offline devil face. BF-55 now delegates **real painting** to `paintFace`, returns false for unavailable/failed providers, and paints local pixel-art fallback only for the player actor/HUD callback. Loaded images, successful painters, and legacy painters that actually draw without a return value continue to report true. Left-facing actor portrait counter-mirroring remains intact.
- Provider priority is host callback, item-local callback, then ready image; unsuccessful/throwing higher-priority painters can fall through to a lower-priority real source. No provider implementation or artwork asset changed.
- Provider contract dependency: a painter reporting false must not have already drawn a finished portrait; a legacy provider returning undefined is treated as successful for compatibility with existing BF-31 tests. A callback that draws an incomplete portrait and then falsely signals failure is a cross-provider contract violation, not detectable without offscreen staging.
