## Coordinate and portrait integration contract
- **Input Canvas context must be in screen/canvas pixels** with no existing game-world camera transform. DPR scaling is allowed upstream. This renderer applies exactly one transform: `ctx.translate(-camera.x*camera.zoom, -camera.y*camera.zoom)`, then `ctx.scale(camera.zoom,camera.zoom)` inside a balanced save/restore.
- The viewport describes the full screen; it is not a crop, offset or second scaling transform. BF-31 compositor should call this routine outside any pre-applied world transform, or pass a temporary identity-screen context.
- `drawPortrait(g, characterId, x, y, width, height)` draws the already-local, ready portrait in the currently translated/scaled and clipped devil faceplate and **returns true** on success. False/throw displays local fallback. The caller is responsible for offline portrait lookup, caching, readiness, and not fetching at render time.
- Devil `x/y` are **top-left**, heli `helicopter.x/y` are craft-centre anchors, `zone.x/y` are actual interaction-anchor world coordinates. No body/viewport-derived re-centering is done.
- Reduced-motion mode freezes rotor, idle sway, particle motion and flashing warning while leaving clear nonflashing telegraphs/boarding indicators.
