## Reproduced bug and correction

The mission keeps boarded players in `state.players` and sets `boarded:true`, `extracted:true`, `status:'boarded'` while retaining their old position and sometimes `alive:true` (`src/engines/broforce/mission.js`). The host passes these flattened snapshots into `advanceBroforceCamera`. BF-19's earlier liveness predicate accepted a boarded player, so the old position could falsely cause `tetherExceeded:true` and pull the shared view away from the actual active player. The new BF-44 test fails on the original pinned camera (boarded hero included in portrait) and passes with the correction.

The camera now excludes explicit `boarded`, `extracted`, `downed`, `dying`, dead/defeated states, named status/state values, and explicitly invalid/zero health. No changes to coordinate transforms, smoothing coefficients, zoom limits, renderers, owner identities, rewards, saves, host caller, module registry, or source art.

## Cross-worker dependencies / remaining limitations

- `src/engines/broforce.js` passes the camera **player snapshots only** (`camera=advanceBroforceCamera(camera,{players,viewport,world,dt,controlsInset})`). Boss and extraction location are not provided as camera focus targets; BF-44 therefore **cannot guarantee boss/helicopter cue visibility if those are away from the living players**. A later host-owning integration worker could add an explicit optional cue-target contract, e.g. `advanceBroforceCamera(camera,{...args,focusTargets:[{x:bossCx,y:bossCy}]})` during boss entry or extraction; that requires a separately reviewed camera API implementation and host wiring. This worker did **not** modify the host or fabricate implemented cue support.
- `viewport.safeInsets` is supplied by the host but BF-19 camera uses `controlsInset` and internal visual margins, not the detailed safe-inset object. HUD/notch clearance requires an actual device/browser review before release.
- When players are farther apart than the minimum-readable-zoom span, `tetherExceeded` remains explicit and physics is unchanged. Off-screen partner indicators or separation policy belong to host/HUD integration, not this camera-only change.
- At hard world boundaries, world clamping can constrain available HUD clearance; only achievable two-actor framing is asserted. No unpainted-world overscroll was introduced.
- No Broforce game selection, boarding receipt, exact devil claim, BF-37 recovery or persistent board state was changed.
