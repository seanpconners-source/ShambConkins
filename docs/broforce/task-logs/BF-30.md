## Exports / input contract

`createBroforceMission({stage,seed=1,devilId,players,attemptId='bf-demo'}={}) -> state`

`advanceBroforceMission(state,{dt=1/60,inputs=[{},{}],paused=false,cancelled=false}={}) -> {state,events,terminal}`

- One mutable authoritative state; pass the same returned state on every update. `stage.tiles === terrain.tiles` inside the mission. The source stage and input players are untouched. State exposes stage/stageId/terrain/world, players/enemies/projectiles/prisoners/devil/extraction, camera placeholder, stats, elapsed/phase and events/fx.
- `players` must be two entries in canonical Sean/Amber order, with a real selected `character` ID. `selectedCharacter` and `character` in the mission are immutable snapshots; `fighterId` alone changes temporarily. Each entry may carry `fighters: snapshotFighters(profile,owner)` from the adapter. `unlockedRoster`/`roster` arrays are also accepted; omission permits only the selected character. Empty/singleton pools work. BF-17 retains canonical identity/alias filtering and never substitutes locked characters.
- The adapter MUST use BF-17 `chooseDevil` for current locked/eligible identity and supply its ID, immutable attempt ID, seed and owner-specific fighter snapshots. Core rejects missing/unknown/special-locked/Loki devil IDs but cannot prove current profile ownership without importing profiles. It never selects an invented Satan or recruits/saves anything.
- Stage uses bounded 16px row-major BF-10 data with two clear 12x26 top-left spawns, enemySpawns/prisoners/devilSpawn/extraction, optional checkpoints and stageId/theme/title. BF-28 is not required. `stageId` falls back to `stage.id`, then `broforce-jungle` for legacy BF-10 fixtures. `stage.timeLimit` or `timeoutSeconds` defaults to 120 active seconds, capped at 600.
- BF-18 inputs are exactly move/jumpPressed/jumpHeld/fireHeld/specialPressed. One special press starts a stationary grounded partner revive within 32px (1.2 seconds, one revive credit per downed player); otherwise it boards a nearby hovering helicopter or throws a finite-ammo grenade. Spawn/revive grace is 1.25 seconds. One hit downs an unprotected player; no checkpoint teleports, automatic continues or team-wipe retries. Checkpoints only emit progression markers.
- Optional `cancelled:true` or `state.cancelled=true` provides explicit exit cleanup even while paused. Cancellation emits the frozen failed envelope once; the host MUST dispose without presenting/settling/calling `s.finish` on exit, consistent with existing launcher cancellation. Pause advances no gameplay clock/RNG and clears pending pressed edges/carry.
- `terminal` is emitted only on the first transition; later calls return null with no events. Immutable `state.terminal` retains the result. Envelope is exactly `{kind:'broforce',won,bf:{schema:1,attemptId,stageId,devilId,outcome,boarded:[bool,bool],aliveAtBoarding:[bool,bool]}}` with no generic scores/rewards. P1/P2/both boarders win; none fail. Boarding receipts survive nonboarder death/global deadline while real departure completes; cancellation still fails.

## Actual subsystem integration / local adapters

- Whole-world 120Hz tick with dt capped at .1 seconds, pressed edges carried through sub-tick updates. BF-13 movement is called once per tick; BF-11/BF-15/BF-20 retain their real 60Hz internal accumulators. Seeded rescue/director/enemy/boss/weapon streams are isolated from presentation.
- BF-12 terrain damage is the sole terrain mutation. Emits full changed tile lists/revision and sound/FX metadata; collision immediately observes holes. BF-14 weapon scheduler preserves per-shot within-tick offsets, magazines/bursts, automatic .8s firearm reload and unique round IDs. Grenades remain finite-ammo.
- **BF-14 contract issue repaired locally:** ricochet subtracts only time-to-contact from `life`, so a grenade stuck at a wall can retain its fuse. Mission subtracts full active delta from retained bouncing grenades and calls the real `resolveBroforceExplosion` on fuse exhaustion. No foundation file/test changed. Real grenade-to-cover-to-traversable-gap integration passes.
- BF-11 grunt/gunner/charger map to BF-15 rifleman/turret/melee. BF-10 scout/sentry/heavy map to rifleman/turret/carrier. Enemy feet align with authored 12x26 spawn anchors. BF-15 target positions are player centres; its telegraphed shots become real slowed BF-14 bullets, not unavoidable direct-ID damage. Hostile bullets target living players only; friendly bullets exclude co-op players. Melee remains contact-checked; carrier blasts use real terrain/explosion logic.
- BF-16 consumes touch or actual attributed projectile/blast cage interactions, resolves duplicate claims and uses each owner's BF-17 snapshot. Swap events never modify board selection. Cages are actual projectile hitboxes, with physical impact/blast provenance required for distant rescue.
- BF-20 boss 58x72 feet align to the BF-10 12x26 spawn; boss activates when a living player approaches within 220px. Real collision hits become unique boss damage receipts; BF-20 owns phases/HP/iframes/defeat. Its shots and area events respect player liveness/grace; cover damage uses BF-12. Defeat alone activates real BF-21 arrival, never victory.
- BF-21 boarding anchor is authored spawn centre (x+6,y+13). Only living nearby special intents before deadline produce boarding/life receipts; boarded players stop attacking/moving. Actual incoming/hover/departure clocks finish the mission.
- Rendering owns the BF-19 camera from `state.camera`; the director uses a deterministic 480x320-or-smaller world view independent of screen resize. BF-25 actor art must receive feet `(p.x+p.w/2,p.y+p.h)`, never top-left as feet. `state.fx` is a per-update array ready for BF-23 event types; `events` contains monotonic mission IDs/ticks, sound cues, authoritative destruction/hit/rescue/boss/heli/terminal events. Host/compositor must consume events once before next advance.
- Phone budgets: 24 enemies, 128 projectiles, 64 prisoners, 32 checkpoint markers, 128 FX requests/update, 2048 events/update, bounded map and mission clocks. BF-20/other foundations retain their own caps; cosmetic drops count in stats and do not create rewards. No particles/DOM/timers/audio contexts allocated by mission.
