## Reproduced defects on pinned base
1. A grenade created inside an indestructible steel tile and advanced through 30 calls of 0.1 seconds remained active with **life=1.25** and **no explosion after 3.0 active seconds**. Every terrain contact occurred at zero travel fraction, so the fuse never ticked.
2. A grenade approaching a steel wall at x=64, from x=40, consumed only the time-to-contact and stopped at **x=63.95** after a 0.1-second call, even though active time remained in the tick. Frame division could change the ricochet path.

## Fix
- BF-14 grenade-only bounded substep loop uses remaining active tick after ricochets, debits actual elapsed fuse time, resolves impact/explosion against the real BF-12 terrain interface, and consumes remaining fuse time if a 12-contact budget is exhausted (never tunnels through solid cover merely to escape a stuck contact).
- Leaves pistol/rifle/shotgun/launcher code paths and projectile scheduling unchanged. Grenade impact/ricochet events retain original shapes. The existing `mission.js` active-grenade fuse correction is redundant but safe: after this fix its `old.life-dt` equals BF-14's new lifetime for surviving grenades. No adapter edit under this task.
- No new weapon system, tuning or reward behavior.
