## Exported APIs and use

- `createBroforceInputState()` is a DOM-free controller with `setMove(owner,source,value)`, `press(owner,action,source)`, `release(owner,action,source)`, `clear()`, and `sample()`; `owner` is index 0 or 1; actions are `jump`, `fire`, `special`. Each `sample()` returns precisely two `{move,jumpPressed,jumpHeld,fireHeld,specialPressed}` objects. Jump/special pressed edges are consumed once per sample; independent source tracking prevents premature release.
- `attachBroforceControls(s,{onChange}={})` attaches after `s.canvas(W,H,{fill:true})` and returns `{sample(),resize(),dispose()}`. `onChange()` is a notification only, not a consuming snapshot. This overlay mounts inside the canvas frame, uses the existing `drag-arena-body` full-fill layout, safe-area spacing and inline namespaced styling, and restores modified inline properties/classes on disposal.
- P1 keyboard: A/D move, W jump, Space fire, E special. P2: Left/Right move, Up jump, Enter fire, Shift special. Active text inputs/contenteditable are exempt. Touch ownership uses the initial **physical** X relative to the visible canvas frame; it never reassigns an active touch after crossing center. Touch sticks and any unused canvas area support horizontal movement; each owner also has jump, fire and special buttons. Holds can coexist across six or more fingers.
- The engine integrator must register `src/engines/broforce/controls.js` in `src/modules.json`, call this controller from the Broforce adapter, sample once per fixed simulation tick, invoke `dispose()` or rely on session cleanup, and coordinate HUD/world-camera transformation. The controller does not change camera orientation or save/profile rewards.
