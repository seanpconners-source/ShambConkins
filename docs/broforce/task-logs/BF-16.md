## Exported public APIs

- `createBroforcePrisoners(spawnList)` creates fresh plain-data cages with stable explicit or index-based IDs and finite pixel-space top-left `x/y`. Default dimensions 16x22. Duplicate IDs/invalid coordinates fail early.
- `advanceBroforcePrisoners({prisoners,players,fightersByOwner,activeFighterByOwner,interactions,rand})` returns new `{prisoners,events}`, does not mutate caller state, and never writes profiles, saves, chosen characters, or the live session.
- `fightersByOwner` must be frozen-in-time owner-specific arrays obtained upstream via BF-17 `snapshotFighters(profile,'Sean'|'Amber')`. This module calls BF-17 `drawNextFighter` for canonical identity dedupe and repeat avoidance. The caller applies emitted swaps to its **temporary minigame** active fighter only.
- Intents: `{type:'rescue',playerIndex,prisonerId?}` (or `type:'touch'`) requires a live adjacent actor (28 world-pixel center-to-cage-rectangle radius). `{type:'cage-destroyed',playerIndex,prisonerId?,x,y}` requires a cage-local hit (16 world-pixel point-to-rectangle radius) and a living attributed shooter, even if the projectile travelled from farther away. Untargeted intent selects only the closest cage. `interactions` accepts an array, or `{actions:[...],cancelled|canceled|aborted|paused:true}`.
- Eligible participants have canonical P1=Sean / P2=Amber `owner` and are not dead, downed, extracted, canceled, `alive:false`, or zero-health. The first claimant for any same-tick collision is deterministic (Sean before Amber), regardless of input order. Cages resolve in stable ID order and cannot be freed twice.
- Output `{type:'fighter-swap',playerIndex,owner,from,to,prisonerId,animationMs:520,statusMs:950}` directs UI/status duration without rendering side effects. If the owner has no legal fighter, emit `type:'prisoner-empty'` with owner/ID/timing and consume the cage once. Singleton pools can legitimately produce `from===to`. The temporary in-function active map chains same-tick swaps but caller maps are never mutated.
