## Source-grounded inspection

Read `AGENTS.md`, `CLAUDE.md`, `docs/AI_STATE.md`, `docs/ENGINE_GUIDE.md`, `docs/broforce/ARCHITECTURE.md`, `docs/broforce/ACCEPTANCE.md`, `docs/broforce/ART_DIRECTION.md`, and the pinned BF-36 adapter, BF-18 controls, GameSession, gameLauncher BF-37 authority bridge, BF-30 mission and the existing host-adapter test. The repo uses browser CommonJS exports, so regression coverage reuses the existing VM loader, not direct Node require of source modules.

No independently reproduced production defect in the owned adapter justified a change. At the pinned base, it:
- Requires one of the four exact stage IDs and matching game ID; validates P1 Sean and P2 Amber regardless of equal/editable display names; snapshots selected fighter and each owner's eligible roster separately from board state.
- Prefers immutable `s.broforceReward.attempt` and validates saved attempt ID/stage/devil without substituting another devil. A prior saved devil that is no longer jointly eligible fails closed.
- Uses one GameSession frame callback, clears held controls on pause, blur, orientation and resize, and tears down CSS, pointer controls, portraits and audio on dispose; BF-18 performs physical-half pointer ownership and BF-19 camera uses current viewport dimensions.
- Calls `s.broforceReward.confirmExtraction({devilId,devilDefeated:state?.bossDefeated===true,extraction:state?.extraction})` **before** `s.finish` for a successful real mission, and converts missing/rejected proof into a failed result rather than an award. BF-37 alone handles persisted exact-devil grants and claims; this adapter never writes profile rewards.
- Provides independent results for P1, P2, both and neither; intro cancel and exit dispose without an award; no Broforce warp zone is created.

This is a code/fixture audit, **not** a claim of verified real-world browser or Android behavior. BF-30 mission modules are mocked by the existing host-adapter fixture, which cannot establish live combat, rescue, helicopter physics or actual persistence.

An explicit fixture-root signature assertion prevents silently using a different test harness.
