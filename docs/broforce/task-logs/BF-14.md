## Public module contract

CommonJS-like `Object.assign(exports,{WEAPON_SPECS,createBroforceProjectile,fireBroforceWeapon,advanceBroforceCombat,resolveBroforceExplosion})`. Pure data interfaces, no DOM, audio or runtime dependencies.

- `WEAPON_SPECS`: frozen `pistol`, `rifle`, `shotgun`, `launcher`, `grenade` descriptions in pixels/seconds, including ammunition, cooldown, magazine, burst count/gap, pellet count, spread, damage, fuse/lifetime and blast characteristics. The rifle fires three-round bursts, shotgun six-pellet spreads, launcher explodes on impact, grenade arcs, bounces and detonates on fuse/target impact.
- `createBroforceProjectile({id,owner,x,y,dir,weapon,angle?})`: returns an independent plain projectile. `id` must be string or safe integer. `dir` is facing `-1/1` or an `{x,y}` aiming vector; `angle` applies radians of angular offset.
- `fireBroforceWeapon({state?,owner,x?,y?,dir?,weapon?,fireHeld?,dt?,seed?,random?})`: immutable weapon scheduler. Returns `{state,projectiles,events}`. State is `{weapon,ammo,cooldown,burstLeft,sequence}`. Consumes up to 0.2 seconds per call; preserves a monotonically increasing per-owner sequence across weapon swaps, but a swap begins a fresh magazine. Caller can provide `random(shotIndex,pelletIndex)` with deterministic results or integer `seed`; RNG is consumed only on actual emitted pellets. `shot` event's `at` is the subframe firing offset in seconds. Integrator must simulate a newly fired projectile for `dt-at` when maintaining full frame-rate-equivalent positioning; it must preserve returned weapon state between ticks. Magazine refills or external pickups are caller-owned state inputs.
- `advanceBroforceCombat({projectiles,dt,isSolid,targets?,worldBounds?,terrain?,friendlyFire?})`: returns `{projectiles,events}`. `projectiles` are advanced without input mutation. `isSolid(col,row)` uses 16px tiles. `targets` are `{id|hitId,bounds:{x,y,w,h}}` or equivalent direct world-pixel box fields; optional `owner/team/kind/dead` determine friendly filtering. `worldBounds` is `{x,y,width,height}`. Defaults suppress all P1/P2 friendly fire. Capsule/ray-style swept collision tests against tile AABBs and target rectangles; wall takes precedence at equal contact time. Returns zero or one authoritative direct hit per projectile-target pair.
- `resolveBroforceExplosion({x,y,radius,damage,terrain?,targets?,owner?,friendlyFire?,explosionId?})`: returns `{events,hitIds,terrainResult}`. Radial hitbox-distance tests, dedupe across chains, radial damage falloff, per-target knockback metadata. An internal optional `chainBlasts` array forwards BF-12's already-applied chain events without damaging the same terrain twice.
- `terrain` accepts the BF-12 world directly or `{world,damageTerrain}`. Only `damageTerrain(world,{x,y,radius,damage})` mutates terrain. Without injected callback, the existing `src/engines/broforce/terrain.js` is lazy-required on impact. BF-12 controls steel immunity and its 64-blast volatile propagation limit.
- `events` include `shot`, `impact`, `hit`, `terrain-damage`, `explosion`, `particles` and `ricochet`. Each combat tick inspects at most 256 projectiles/256 targets, returns at most 256 events; one explosion's particle metadata never exceeds 48 count. The summarized terrain-event arrays cap at 32 entries while preserving total counts.
